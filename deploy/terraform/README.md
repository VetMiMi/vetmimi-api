# Terraform

Each directory is a root module with its own local state (gitignored),
initialised and applied on its own by the owner, never by an agent. CI runs
`terraform fmt -check`, `init -backend=false` and `validate` on every root; that
proves the code is well-formed, not that an apply would succeed.

| Root | What it holds |
|---|---|
| [`budget/`](budget) | The monthly cost budget for resources tagged `Project = vetmimi`. Separate state, so destroying the host never destroys the alarm. Apply it first and leave it |
| [`live/`](live) | The live host of ADR-010: EC2 `t4g.small`, Elastic IP, security group, instance role, media and backups buckets, ECR repositories, GitHub's OIDC release role, CloudWatch alarms |
| [`demo/`](demo) | ADR-005's Fargate topology, applied once for evidence and destroyed the same day: VPC in two zones, ALB, two CloudFront distributions, ECS Fargate `api`, `worker` and `web`, RDS PostgreSQL Multi-AZ, ElastiCache Redis, a media bucket, alarms |

The runbook is [`../README.md`](../README.md).

## Conventions

- Provider versions are pinned in each root's `versions.tf`, and each root's
  `.terraform.lock.hcl` is committed with hashes for `darwin_arm64`,
  `linux_amd64` and `linux_arm64`. After changing a version, regenerate it
  with `terraform providers lock -platform=darwin_arm64 -platform=linux_amd64 -platform=linux_arm64`.
- Real values live in `terraform.tfvars`, which is gitignored; each root ships
  a `terraform.tfvars.example` with placeholders only. No account id, email
  address or secret appears in a committed file.
- Every resource carries the provider-level tags `Project`, `Environment` and
  `ManagedBy`.

## The Fargate demo

`demo/` runs the same images as the live host on ECS Fargate (arm64) across
two availability zones: `api` (2 tasks, CPU scaling to 4), `worker` (1) and
`web` (2) behind one load balancer, with RDS PostgreSQL 17 Multi-AZ and
ElastiCache Redis. There is no domain, so each service gets HTTPS from its own
CloudFront distribution; the load balancer admits only CloudFront, and only
requests carrying a distribution's secret header. Secrets are generated by
Terraform into Parameter Store. Everything is built to come down with one
`destroy`: no final snapshot, no deletion protection, `force_destroy` on the
bucket. The repositories in `live/` are only read, never changed.

Left out on purpose:

- Video calls. Fargate cannot publish a UDP range for TURN, and the signalling
  hub lives in one api process, so two participants on different tasks never
  meet.
- Media uploads. The API signs S3 requests with the EC2 instance role only,
  which a Fargate task does not have; the task role is ready for when it uses
  the SDK's default credentials.
- Email, unless you pass `TF_VAR_resend_api_key`; without it each send fails
  and is recorded as failed.

### Run it

You need `budget/` and `live/` applied, the two images already in ECR (each
repository's `release.yml` pushes `:<sha>`), Terraform 1.9+ and the AWS CLI.
Put the two full commit shas and your email in `terraform.tfvars`.

```sh
export AWS_PROFILE=auvan-tf
cp deploy/terraform/demo/terraform.tfvars.example deploy/terraform/demo/terraform.tfvars
terraform -chdir=deploy/terraform/demo init
terraform -chdir=deploy/terraform/demo apply
terraform -chdir=deploy/terraform/demo output
```

The apply takes about 20 minutes, mostly the Multi-AZ database and CloudFront.
Confirm the SNS email, then open `site_url` and `api_url`/readyz.

Screenshot, with the account id blurred, into `docs/evidence/` as `.webp`:
the ECS cluster's services and tasks (`aws-ecs-service`), the database's
Multi-AZ configuration (`aws-rds-multi-az`), the CloudWatch alarms
(`aws-cloudwatch-alarms`) and the budget (`aws-budget`). Then capture the CLI
evidence; it forces one rolling api deployment while it polls `/healthz`:

```sh
deploy/terraform/demo/evidence.sh > docs/evidence/cli-evidence.txt
```

Destroy it the same day, then check the Tag Editor finds nothing tagged
`Environment = demo`:

```sh
terraform -chdir=deploy/terraform/demo destroy
```

If the apply stops at the media bucket policy with `AccessDenied`, the
account blocks public bucket policies, as described for `live/` in
[`../README.md`](../README.md).

### What it costs

Estimates for `ap-southeast-2` in US dollars, from on-demand prices; check
the budget afterwards for the real figure.

| Item | Per hour |
|---|---|
| Fargate arm64, 5 tasks of 0.25 vCPU and 0.5 GB | 0.06 |
| RDS `db.t4g.micro` Multi-AZ with 20 GB gp3 | 0.06 |
| Application Load Balancer | 0.03 |
| ElastiCache `cache.t4g.micro` | 0.025 |
| 7 public IPv4 addresses (tasks and load balancer) | 0.035 |
| CloudFront, logs, alarms, S3, Parameter Store | under 0.01 |
| **Total** | **about 0.21, so about 5 a day** |

A four-hour session costs about a dollar.
